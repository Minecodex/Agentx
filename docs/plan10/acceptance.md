# plan10 验收矩阵

状态：`complete`。31 项适用系统门禁、三类真实页面和 6 批次/18 项业务通过，临时资源与凭据已清理。下列保留验收要求；实际候选、通过结果和原始失败见 [实施记录](evidence/implementation.md)。Demo 不计入系统验收。

## 1 验收环境和入口

系统测试唯一编排入口继续使用：

```sh
uv run --frozen --group test pytest tests/e2e
```

已使用该入口启动独立临时环境，复用 [E2E 标准](../plan/e2e-testing-standard.md) 的临时 Kubernetes 命名空间、Rust 部署工具、测试依赖和证据设施；由 Python 准备环境、管理进程、调用现有 TypeScript Playwright、收集证据并最终清理。不得另建绕过编排的系统验收脚本。

浏览器验收以 1440×900 桌面为基准，覆盖现有语言和明暗主题的受影响交互。移动端导航、窄屏和移动专属操作不属于本期产品验收。故障实验使用可控测试依赖；正式业务调用仍通过真实发布和现有 Runtime，不能用前端计时器代替。

需要缓解资源压力时复用现有 `--scale-down-development` 能力，记录测试前副本，在最终清理中恢复；不默认修改常驻环境。具体已有参数按测试入口定义传递，不在本计划另造命令。

## 2 契约与原子受理

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| E10-C01 | 1、100 项有效输入；0、101 项、超过 1 MiB、混合 Schema 错误 | 合法请求完整受理；非法请求返回批次/行/字段定位，不创建任何部分调用或残留有效批次 |
| E10-C02 | 同键并发提交、受理后响应丢失、重试、同键异值 | 同一主体/应用/操作返回同一批次；异值冲突；错误不触发新的业务意图 |
| E10-C03 | 两条内容完全相同但行 ID 不同；重复行 ID；公共参数合并 | 前者生成两个独立项目；重复 ID 拒绝；每项保存完整规范化输入与原始顺序 |
| E10-C04 | 1–50 分页、筛选、无效游标、跨主体复用游标 | 边界正确、无漏项/重复；一次查询聚合与项目状态一致，非法游标无法跨对象读取 |

## 3 派发 故障与操作

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| E10-R01 | 受理提交后关页、断网、服务重启；派发前进程终止 | 完整输入和引用仍在，后台继续；返回原页面可查回原批次，不依赖浏览器队列 |
| E10-R02 | 受理 Invocation 后写关联前强退、重复 Outbox、双副本、租约失效、Redis 重建 | 一个项目收敛到同一个原 Invocation；不丢关联、不重复受理，事件和租约可追溯 |
| E10-R03 | 多个项目同时待输入/审批、其他项目可运行；队列限流和依赖瞬断 | 等待不占 Worker；其余项目在配额内推进，批间公平；瞬态背压保留排队，不伪造业务失败 |
| E10-R04 | 停止与受理同时发生；持有旧租约的副本继续尝试 | 停止后未受理项目不能新开调用；先受理项目继续，状态和计数无遗漏 |
| E10-R05 | 取消排队/执行/等待项目及不可取消项目；取消请求断线重复 | 先停止派发，复用原取消规则；受理与实际结束分开，已产生外部效果不被宣称回滚 |
| E10-R06 | 可重做失败、已完成、待核实及不可重放副作用项目；重做时契约变化 | 仅允许集合形成新派生批次，绑定当前发布并重新审批；原历史保留，未知/不安全项目禁止直接重做，契约变化需显式修正 |

E10-R02 必须在故障点有确定触发和恢复证据，不能仅依靠多次随机重启。业务任务、工具调用和外部副作用分别核实，不把「无重复 Invocation」等同于任意外部系统 exactly-once。

## 5 身份 文件与安全

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| E10-S01 | 跨租户/应用/员工读取批次、项目、单项和导出；猜测 ID 或伪造 userId | 所有路径做对象授权，客户端声明不成为可信身份；服务 Key 不能冒充员工 |
| E10-S02 | 管理列表权限不足、正文/Trace/附件权限不同；运行中撤权、停用或撤销 Key | 摘要不扩大敏感数据权限；当前 Admission 在逐项受理时生效，后续项目拒绝原因可追溯 |
| E10-S03 | 错属附件、共享文件、未派发文件、取消/派生及保留任务 | 受理前有引用保护，转交与回收正确；不能借批次或导出下载他人文件 |
| E10-S04 | CSV/TSV 引号、换行、编码、空行、公式文本、超限、URL/路径或伪 XLSX | 解析有界并定位错误；不执行公式、不拉远程文件、不读取本机路径，错误不产生业务调用 |
| E10-S05 | 导出排队/执行/等待/成功/失败/取消/待核实混合快照，输出权限和币种不同 | 文件与冻结快照一致，状态无伪成功；权限、公式转义、下载归属、币种分组和审计均正确 |

参数式单项不共享 Session。用户记忆仍使用既有可信来源作用域，需检查批次实现没有把 batchId/itemId 或传入姓名作为新记忆身份；不要求同一用户的不同项目拥有从未定义过的记忆隔离。

| E10-U04 | 项目分页、状态筛选、单项执行记录、多个并行待办、原审批跳转 | 查询和允许动作准确；审批决定仍在原审批中心，未授权页面不能批准 |

| E10-U06 | 停止、取消、失败项派生、导出进行中/失败/完成 | 文案区分真实作用与状态，原批次可追溯；敏感/无资格操作不可由客户端绕过 |
| E10-U07 | 从检查结果或预览页启动同一份已保存 HTML 的检查 | 检查前预览已可见，检查期间不能切换页签；同一源码的检查结果一致，不因宿主隐藏预览误报字段、行数或提交失败 |
| E10-U08 | 统一模型管理的新建/编辑思考深度及中英文、明暗桌面 | 与默认参数 JSON 同步；保存 max 保留其他参数并创建新配置版本，刷新后仍正确；编辑不产生模型请求。脚本诊断定位原始 HTML，排除平台注入 SDK/样式的行数 |

可访问性检查覆盖键盘、明确标签、错误关联和动态反馈。视觉检查覆盖文本/按钮不遮挡、表格可读、加载/空/错误状态，不用主观评分代替业务断言。

## 7 真实 AI 页面与正式运行

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| E10-A01 | 从原 AI 页面创作入口提出批量需求，并持续修改当前工作页面 | 使用现有模型/Host/Core；记录原始回复、工具、HTML 与检查结果，无第二套模型配置或硬编码业务页面替换 |
| E10-A02 | 创作、导入、模拟检查、历史模拟、拒绝发布/提交 | 设计态无正式业务 Invocation、审批或发布副作用，模拟数据与真实数据边界可检查 |
| E10-A03 | 多业务生成页面正式发布、提交、关页恢复及结果处理 | 下述最低样本全部走正式调用，页面字段、等待和输出来自真实契约，记录批次与原 Invocation |
| E10-A04 | 原单项网页、本人记录、文件、API、会话、既有 MCP 与权限系统回归 | 旧有能力继续通过其正式验收；不把本期未提供的新 MCP 批次工具算作已交付 |

E10-A03 最低样本为三种不同输入/输出及交互的应用，各通过真实创作得到至少一份页面；每份页面用两组全新数据各提交一个至少三项的批次，即至少 3 份生成页、6 个正式批次、18 项。该数量是覆盖门槛，不是负载或模型稳定性认证。

| 业务样本 | 覆盖重点 |
| --- | --- |
| 费用报销 | 数字/币种、多个并行补充与审批，其余项目继续 |
| 客户报价 | 公共参数与逐行参数、结构化输出、部分失败与符合资格的派生重做 |
| 文件分析 | 每项文件归属、异步完成、分页结果、汇总导出和历史页面恢复 |

测试业务可按实际可部署能力调整名称，但不能删除覆盖点。待输入、审批与故障场景使用明确可控条件，不能依赖模型随机决定。页面修复保留首轮结果和修复轨迹，禁止先手写固定页再称为真实生成。

真实模型验收使用用户显式提供的 APIMart `glm-5.3-flash` 测试连接；累计费用上限 30 美元、上游请求最多 190 次、每次输出最多 16,000 tokens，覆盖修复与复测。请求上限原为 100 次，用户于 2026-11-03 依次明确授权追加至累计 150、160、180 次，最后回复「允许追加到 190 次，完成明细修复和验收」；既有计数、已结算费用与未知预留完整沿用。当前测试模型显式配置 `reasoning_effort=max`，转发审计只保存参数、请求摘要和预算关联，不保存密钥或正文。复用同一持久预算账本，未知计费请求保留预留上界，不重置账本。密钥只保存在临时私有配置中，证据与文档不记录明文。

## 8 完成证据

每项证据关联用例 ID、候选源码和差异、镜像 Digest、环境、发布/Bundle/SDK、主体、batchId/itemId/invocationId、关键权限/状态快照、命令与结果。跨层对照来自授权业务视图和权威存储，Trace 用于定位问题而非定义完成。

本地输出进入 `.local/artifacts/plan10/<run-id>/`，保留 Playwright 报告/Trace、必要截图、故障点、恢复时间线、脱敏 API 结果、日志、模型用量/费用与清理清单。不得保存明文 Token、密钥或无关敏感正文。

完成条件：全部适用用例通过；强制用例没有 skip/xfail；不适用项有具体前提和理由；原失败与专项复测均可查；所有临时命名空间、进程和发布物清理完成，开发副本恢复。任何功能未实现、契约漂移、待核实副作用未处置或清理失败，都不能把 P10-06 标为完成。

本计划不自动关闭 plan7/planv2 的生产容量、安全或灾备认证，也不把 Demo 检查记作产品系统验收。
