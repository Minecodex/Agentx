## 3 P10-01 Runtime 批次受理与查询

- [x] 在 Runtime 初始化 DDL 中增加批次、项目和必要索引/引用，定义完整输入、稳定行 ID、真实主体、Bundle、页面修订和来源关系。
- [x] 实现整批原子校验与受理、持久输入和附件保留；创建幂等涵盖断线重试、同键异值冲突及内容相同的不同业务行。

- [x] 为冻结 Bundle、页面物料、输入文件和未派发项目建立必要引用，覆盖受理失败和取消的清理路径。

## 4 P10-02 后台派发与恢复

- [x] 在现有 Runtime 产物中增加批次协调模块，以有界并发复用正式 Invocation 受理；应用/租户/资源准入保持有效。
- [x] 接入既有 Outbox、恢复和租约机制，覆盖重复派发、主副本切换、受理后关联前强退及 Redis 重建。
- [x] 人工等待与 Worker 解耦；其他项目公平推进，同时遵守租户总在途限额。限流或依赖瞬断仅使未受理项目退避。
- [x] 实现停止修订与受理串行、取消未结束项的逐项受理/结果，以及当前撤权和停用检查。
- [x] 实现有资格的失败项创建新派生批次、当前发布重新校验、原对象保留和来源链接；待核实或不安全重放的项目禁止直接重做。
- [x] 增加批次/项目关联的结构化日志和观测字段，继续由原调用记录模型/工具消耗，不重复计费或累计成本。

退出门禁：E10-R01 至 R06 通过，所有崩溃恢复证据可关联 batchId/itemId/invocationId；未发现重复受理、停止后越界派发或跨版本混用。

## 5 P10-03 SDK 与 AI 页面创作

- [x] 将批次能力接入可信宿主和受限 SDK，保留绑定应用、稳定请求键、大小/并发限制、历史模式和对象归属检查。
- [x] 实现 batchId 初始上下文和 openBatch 精确历史恢复；与原 taskId 路由互斥，缺失/损坏发布物明确失败。
- [x] 使用批次分页和有界刷新，单项下钻复用原查询/订阅；禁止每行占用一个长期订阅或在 HTML 循环 invoke。
- [x] 向原设计态 Host/Core 提供批次契约和能力，继续使用平台统一模型配置与工作 HTML，不新增页面独立配置、创作入口或自动后端生成。
- [x] 扩展静态/隔离检查：单项一次提交产生一个任务，批量一次提交产生一个批次及准确 N 项；覆盖异步、并行等待、分页、输入保留和历史场景。
- [x] 确保创作、解析、校验和预览均无正式业务调用或发布副作用；真实测试和发布仍由原可信 UI 明确发起。

## 6 P10-04 管理与员工入口

- [x] 复用现有桌面侧栏、应用详情页签、共享组件、字体和主题，在「访问界面」展示批次能力与原发布流。

## 7 P10-05 导入导出与保留闭环

- [x] 复用仓库 Rust `csv` 实现 CSV/TSV/粘贴解析和定位，支持显式列映射；不新增未审计的浏览器解析包或原生 XLSX 能力。
- [x] 解析前后分别限制文件/返回大小与行数，检查编码、引号、结构化值及附件归属；解析不创建业务任务。
- [x] 实现服务器快照 CSV 导出、生成状态和授权下载，记录契约、状态、来源、错误、输出与币种；对公式触发文本进行导出转义。
- [x] 验证共享附件、未派发引用转交、停止/取消、派生批次、历史页和导出文件的保留/回收；禁止绕过对象存储授权。
- [x] 补齐创建、管理操作、下载、撤权和拒绝的审计事件；批次摘要权限不能推导为正文或文件权限。

退出门禁：E10-S01 至 S05、E10-U02/U06 及 E10-V03 通过；Retention 实验没有提前删除仍需文件，也没有留下无归属引用。
