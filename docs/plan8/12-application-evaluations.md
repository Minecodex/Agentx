# 应用测试集与平台 AI 评测

状态：已实现并完成本地定向验收。此设计取代全局测试集、独立规则评测方案和全局评测报告管理入口。代码、分轮测试及环境恢复记录见 [验收证据](evidence/2026-10-18-application-evaluations.md)。常驻数据库重置和部署不在本次范围。

## 业务边界

测试集、评分方案和评测批次属于应用，正式运行目标为应用关联工作流的已发布版本；本次不扩展会话、渠道、用户记忆或文件正文评测。应用详情通过“测试与评测”管理测试集、评测记录和评测方案。

测试集创建时冻结完整输入输出契约。同契约的多个工作流版本可以共用测试集；字段增删、改名、类型、必填、默认值、枚举、文件限制等变化要求创建新测试集。显示标题、说明和无语义排列变化不影响契约指纹。规范化按 Schema 位置识别关键字，不能删除名称为 title/description 的业务字段。

用例允许保存待补全草稿。复制只按相同路径、类型及目标约束带入数据，保留稳定来源标识；不猜测改名、不转换类型。从外层测试集列表发起复制并选择目标工作流版本；契约变化时，所有复制用例统一撤销参考确认、进入草稿，逐条检查确认后才能评测。契约相同则保留原准备状态，原测试集始终不变。不再提供批量补充缺值功能。调用记录使用实际执行的输入、输出和版本，输出由用户确认为参考答案。整集校验通过后才能生成不可变数据快照并评测。

调用记录“加入测试集”进入后立即使用服务端固定契约及附件授权检查数据。完整样本在同一个确认窗口选择匹配测试集或新建测试集，点击“确认加入”即确认参考输出；缺项样本直接打开右侧编辑框，按当前内容重新校验。测试集名称与自动生成、可编辑的用例名称使用不同标签，切换目标或展开编辑保留输入，不串联“先建空测试集，再填写首条用例”的弹窗。新建测试集及首条用例在一个事务中保存，失败全部回滚。真正缺项可保存草稿；仅参考答案未确认的已有用例显示“待确认”，不显示为字段“待补全”。错误携带稳定代码，界面本地化显示字段路径和当前问题，不复用历史校验提示。

测试集列表提供编辑、从此测试集创建；用例列表提供勾选与全选后导出，导入与导出相邻、新增用例置于最右侧。导出请求携带用例 ID 和来源修订，只输出选中记录；空选择、跨集 ID、过时修订均拒绝。沿用 dataset:view 导出和 dataset:manage 导入权限，不新增独立权限。

## 执行与授权

创建评测时必须填写名称，逐行先选测试集再勾选其适配的已发布工作流版本；每集可选多个版本，不预选被测版本。批次固定评分方案、平台模型、凭据、参数、价格和系统评分提示词。每个“测试集快照 × 工作流版本”生成一个 Runtime WorkPackage，Control 持久派发并幂等恢复。质量未通过与执行/评分异常分开记录，评分异常没有伪造的零分。

现有画布模型设置扩为一个平台 AI 模型设置，供画布和评测共用。该修改正式扩展原先仅设计态的授权用途。被测工作流仍使用自身运行身份；系统裁判具有独立、签名保护的平台评测授权和模型资源，不得将裁判资源加入业务工作流可用集合。裁判没有工具能力。

评分方案仅保存自然语言标准和通过阈值。模型返回 0–1 的 score 与 reason，平台按阈值计算通过状态；界面展示 0–100，默认通过分为 80。普通模型切换只影响新批次，资源停用/撤销遵循现有治理约束。

## 报告与历史

评测记录按名称、评测方案、测试集、工作流版本、完成任务、平均分、状态、时间展示。测试集和被测版本按行对应；平均分按已评分用例数加权，评分错误不计为零分。

同一测试集快照按版本比较改善和退步；跨测试集按复制来源显示对应关系并标注数据变化，不以平均分生成无条件优劣结论。输入、参考输出、实际输出、完整评分理由、业务/评分 Trace、分开计费和操作错误均可查看。

直接修改初始化 DDL、契约和调用方，不迁移历史数据，不保留全局旧路由或旧评分器。常驻数据库重置和环境发布不在实施范围。

## 工作流输入交互

中间回复和输入等待统一归入 `agentx/core`，持久化与恢复由 Runtime 承担。`input_waits`、`workflow_messages` 和 `channel_input_receipts` 分别保存等待、消息和渠道幂等凭据；Hook 复用 delivery outbox。平台入口共享等待节点发现及回复序列编辑器，定时和测试用例版本冻结 `waitInputs`，评测投影保存实际等待和消息。详见 [工作流交互协议](../14-workflow-interactions.md)。
