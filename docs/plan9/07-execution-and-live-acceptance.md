## 依赖与环境

rmcp 固定 3.8.0，应用 MCP 协议验收基线 2025-11-25，显式设置协议版本；现有工具调用/测试服务必须回归。SDK 的 MSRV 为 Rust 1.88，因此 workspace 的声明最低版本同步提高；仓库固定工具链 1.97.1 无须更换。

OAuth 使用自托管 Ory Hydra 并衔接现有登录和授权 UI，令牌支持撤销/introspection；服务调用保留应用 Key 主体。部署在依赖域，数据库与密钥独立。

系统 E2E 由 `uv run --frozen --group test pytest tests/e2e` 唯一编排；浏览器操作使用现有 TypeScript Playwright。复用临时 Namespace、agentxctl、镜像和证据基础设施。测试成功或失败都清理临时环境，必要时缩容开发服务后恢复原副本，不自动升级常驻部署。

## 真实模型与预算

仅使用用户指定的 APIMart `glm-5.3-flash`。供应商地址为 `https://api.apimart.ai/v1`；真实测试配置显式注入，不自动从常驻部署取凭据。APIKey 不写入本文、源码、命令行参数或证据。代理凭据、模型参数、单价与请求限制都必须明确，配置无效直接失败。

全部网页生成、修复、压缩、业务模型和独立客户端请求共享一个持久预算账本，USD 上限 30、真实上游并发最多 2。发请求前按输入/输出上限预占，按实际 Usage 结算，响应未知/缺失 Usage 保留预占；恢复进程不能清空已消费或待核实额度。超预算停止新请求，失败/未执行项不能标为完成。

## 场景和完成标准

基础 20 类工作流先通过同一个 session 级 MCP 协议验收 fixture，完成实际提交、补充输入、主管审批、输出和文件检查后，才允许启动画布创作链或基础页面生成。该 fixture 在同一环境只执行一次；流程定义错误不能转交页面 AI 修改 HTML。Code 的 `outputExample` 使用数学数值推导类型，金额、单价、折扣和重量采用带非零小数部分的示例，数量仍为整数；验收业务输入和预期结果不随示例类型修正而改变。

20 类工作流分别覆盖：标准报价、多行采购、订单校验、单文件报告、多文件对比、多轮会话、文字补充、结构化输入、连续等待、条件等待、并行等待、子流程等待、循环复核、经理审批、双人依次审批、阈值审批、工具批准、工具拒绝重提、输入后工具审批、异步报告。

每类三轮采用默认、紧凑突出结果、历史与进行中任务三种需求，使用新的应用草稿/创作会话生成，共 60 份真实页面。再对 S08/S12/S14/S19 验证真实画布 AI 创建工作流后创建页面，共至少 64 份页面，每份两组未参与生成的输入，至少 128 次网页执行。

允许首次端到端失败后再给 AI 两轮诊断/修复，禁止人工修改 HTML 代过关；保存首次成功率、修复后成功率和全部失败材料。最终所有场景均须通过。E9-G04 另在 S01 第一轮初稿后测试一次明确的自然语言布局调整，单独记录该修改 Run、前后 Hash、费用和结果；它不重置生成/失败修复预算，也不能用于追加修复已耗尽的页面。

四条完整创作链按错误归属提供反馈：已验证网页正确提交输入，而正式 Runtime 失败或实际输出不满足业务断言时，立即停止页面修复，将脱敏工作流诊断交给画布 AI；不能让页面伪造结果掩盖工作流错误。每条逻辑链的画布创作和页面创作各最多三个真实 Run，静态修复与跨版本修复都累计，版本、草稿和会话变化不能重置额度。画布修复后按正式版本编辑/发布流程重新冻结 Bundle，再由页面 AI 创建匹配界面；所有旧版本、失败任务、HTML 和 Effect 收据保留。存在未结算或未知的业务工具 Effect 时，不开始新的业务验证。测试侧只读分析 Python 入参名称以提供诊断，不代替 AI 修改业务代码。

AI 创建的工作流使用其实际不可变发布版本中的节点路径。测试在页面生成前按节点业务职责、类型、字段及指定子流程版本绑定两组预留输入，保存映射；不要求 AI 复用预置流程的内部节点 ID。匹配歧义、业务字段变化或子流程版本错误均失败，不猜测。该步骤只调整测试路径，不修改 AI 工作流、HTML 或业务数据，也不把测试输入发送给创作模型。

报告分别保留完整创作 Run 的首次通过率和 Agent 第一次模拟预览的通过率。一个 Run 内可能包含自检修正，不能把这种情况宣称为首份 HTML 一次通过；首次模拟检查缺失时单列，内部工具错误和外部修复分别计数。

重复静态/交互检查必须从新的隔离 DOM、端口和合成任务状态开始。使用会在提交后收起初始表单的实际 AI HTML 验证：每轮均能提交、处理结构化等待，且前轮任务不进入新场景。保留修复前同一 HTML 首次检查通过、再次检查误报的原始证据；该合成复核不增加真实页面或正式业务执行数量。

正式、历史及跨入口文件下载共用同一浏览器检查：先确认约定的 `download-file` 动作可见，再同时接住下载事件与点击的失败。缺少标记、点击失败或没有下载事件都应成为可反馈给 AI 的普通失败，不能因未处理的异步超时提前终止剩余修复。独立的两个合成浏览器反例验证失败后仍可继续下载，不计入 64/128；报告以数据库中真实启动的 Run 数量核对尝试数，包含尚未写入完成报告就被中断的 Run。若修复的是测试编排缺陷且产品源码不变，新完整候选可复用原已核验镜像和检查证据，同时记录新的测试源码身份，保留旧候选全部失败。

画布创作失败后的剩余 Run 必须保留实际本地文档；若重载出现“恢复本地修改”，通过正式 UI 恢复原副本后继续。保存失败记录实际 HTTP 错误码、消息和字段诊断，不只记录“已保存”状态等待超时；下一次 AI 修复收到同一原始业务需求及这些诊断。Runtime 调用证据保留脱敏错误消息，区分提供方拒绝、连接不可用和业务失败；发现集中外部故障时停止无效生成，保留已耗尽尝试，不通过换模型或追加第四次绕过。

创作模型中断时保留原 Run/Effect 的未知状态及费用预占；若仍有修复额度，验收方可发起新的草稿修复 Run，先读取已经确认保存的页面，不重放旧 Effect 或编辑命令。这仍计一次外部修复。业务工具写入结果未知则停止该页面的业务重试，保留原任务待核实；不能以修复页面为由重新提交未知写入。

每页严格限制首次生成加两次外部 AI 修复，失败候选的页面不通过重启或新会话获得第四次尝试。临时服务故障若发生在模型派发之前，按原 Run ID 查询权威 Runtime 账本，跨来源确认调用记录为零，保留查询时间、原状态、原 HTML 和启动失败，单列为未派发诊断；不能仅凭缺少 Usage 推断没有调用，也不据此增加本页次数。平台修复后的新候选使用新临时环境执行完整矩阵，旧候选及其失败报告继续保留。部分输出、Provider 拒绝、超时或费用未知的调用仍保留原记录及费用预占。

取消运行中的任意程序只能报告已确认的事实。服务端返回 `outcome_unknown` 时，页面须明确展示待核实状态、保留原任务、禁止自动重放，不能伪报已取消。取消用的额外测试请求采用独立业务标识，不替代每页两组必须完成的正式输入；文件仍须通过授权下载和内容 Hash 验证，员工页面无需显示 Artifact 内部标识。

全部 20 类通过 MCP 协议测试；S01/S04/S06/S08/S11/S14/S18/S19 通过本机 OpenCode 1.1.56 自主工具调用验证。外部 AI 仅获得当前应用 MCP 能力，禁用本地文件、Shell、编辑与子 Agent；审批由 Playwright 主管账号在可信审批中心完成。

MCP 基础协议实测若遇到正式任务已失败、且所有错误均明确为模型流缺少 `finish_reason`/`[DONE]` 的中断，保留原任务、Effect、已确认写入和未知用量。核对原 CRM 写入次数后，允许最多两次新的协议复测：每次使用独立客户端与请求身份，按应用原有 Schema 更换已声明的业务编号，保留业务字段、输出断言、审批、文件和取消检查；对话以新客户端的正式会话开始。不恢复或重放旧任务。无法核对写入、出现额外写入、工具结果未知、普通业务/Schema 错误均不得使用此复测。首次协议成功率、复测次数、原失败和最终结果单独报告；此规则不增加画布或页面最多三个创作 Run 的额度，也不能将失败任务计为正式成功执行。

既有 38 项验收及相关回归继续有效。证据写 `.local/artifacts/e2e/<run-id>/`，包含候选身份、HTML/契约/SDK/Bundle Hash、真实执行/审批/文件、首次失败与修复、Token/费用、清理结果；脱敏汇总进入 docs/plan9/evidence。
