# AI 应用界面与静态页面托管

状态：complete。对应讨论第 3 项。原始 64 份真实 AI 页面完成 128 次合格网页执行，含未修改 S13 原页的独立复核；历史、隔离、发布和恢复门禁通过，见 [最终报告](evidence/2026-11-02-acceptance.md)。管理员为已发布应用生成业务页面，员工通过稳定地址登录使用；本方案替换固定模板工作台。

## 1. 应用内管理与员工入口

应用详情的“访问界面”Tab 使用单一工作页面：左侧是当前 HTML 的预览，右侧是与该页面持续绑定的 AI 聊天。顶部仅保留打开页面、发布和发布历史等轻量操作，不展示新界面、草稿选择或独立发布配置区。HTML 可只读查看，修改统一通过右侧聊天完成；内部修订和不可变发布绑定仍用于并发与执行一致性，不作为创作步骤暴露。

| 管理动作 | 行为 |
| --- | --- |
| 初始化界面 | 首次进入自动准备当前应用的唯一工作页面，用户直接在右侧描述需求；不自动发起付费生成 |
| 对话修改 | 持续修改同一 HTML，重新打开仍恢复本人原会话；内部保留修订、Hash 和冲突检查 |
| 预览 | 使用合成数据和隔离 SDK 展示加载、等待、结果、失败等状态，不执行工作流 |
| 测试 | 用户明确选择测试部署并提交实际输入，产生正式可追踪的 Invocation |
| 发布 | 首次点击弹框填写 `/a/` 后缀；之后点击沿用已有 URL。校验通过后原子发布当前页面与其业务绑定 |
| 发布历史 | 在独立历史预览中查看当时冻结的 HTML、SDK、样式和契约，回滚只切换线上完整发布；不替换当前编辑 HTML、不新建或清空聊天 |

应用目录只增加“打开应用”和“复制访问地址”。员工直接访问 `https://agentx.example/a/sales-quote`，无需先进入目录或管理页。当前编辑页面及聊天与发布历史相互独立：历史回滚之后继续发消息仍修改回滚前的工作页面，再发布则用该工作页面更新线上内容。若希望把历史外观用于当前编辑，用户须在聊天中明确描述需求，由 AI 修改，不提供“恢复为草稿”操作。

## 2. 生成上下文与基本可用标准

生成 Agent 复用 [同一个模型与设计态底座](06-shared-design-agent.md)，输入至少包含：

- 应用用途、管理员原始需求、目标用户和明确限制。
- 实际发布部署、工作流版本、完整输入/输出 Schema、字段说明、枚举、默认值、文件类型与样例。
- 可公开的过程阶段、输入等待及 responseSchema、正式会话/ChatMapping 契约；只有实际声明的交互才生成动作。
- SDK 类型/错误契约、平台样式/基础控件、主题、语言与桌面要求。
- 当前页面源码/修订、契约 Hash、待解决检查；实际输出只读取用户明确选择且有权查看的脱敏样例。

未填写需求时，AI 依照契约生成包含字段说明、校验反馈、提交/防重复、运行状态、结果和文件的初稿。有需求时可组合表单、对话、表格和图表，不强制套用固定模板。输入输出没有某字段或能力时，不能为美观虚构业务数据、接口或完成状态。

例如“报价页面，左侧填写客户与产品，右侧显示明细和总价，支持下载报价单和查看自己的记录”，应生成已绑定正式 SDK 的完整交互。动态选项只有应用契约或明确受控能力提供时才能使用，不让 AI 凭空增加查询 CRM 的接口。

首版不建设通用批次管理。工作流接受数组时，页面可编辑数组并作为一次输入提交；逐行独立任务、后台批次派发、跨任务导出不是自动获得的能力。

## 3. HTML 发布物与统一样式

页面主体是一份标准 HTML，包含受支持的内联 CSS/JavaScript。平台注入固定版本的 SDK、设计令牌、字体/图标和原生 DOM 基础控件样式；只适配需要的现有组件能力，不另建主题或完整组件库。HTML 不依赖每应用 React 构建、npm 安装、CDN 或专属服务。

统一样式为长结果值提供容器内换行，文件 Hash、标识和摘要不能挤入相邻桌面字段。浏览器以真实文本排版范围验证，而不是只检查 CSS 字符串；该规则随样式发布物一起冻结，不能在历史页面之外临时替换。

| 发布物字段 | 约束 |
| --- | --- |
| HTML Artifact、Hash、大小 | 不可变；源码与发布成品可核对，不执行服务端模板 |
| SDK/样式版本 | 明确绑定平台支持版本，不能由模型下载或改写 SDK |
| application/deployment/Bundle | Host 注入的目标，不接受页面自行选择其他应用或版本 |
| input/output/interaction Contract Hash | 覆盖输入、输出、文件、等待与会话契约，校验失配阻止发布 |
| 来源 | 页面草稿修订、创建者、生成 Run、Prompt/工具版本、校验报告 |

大图像和业务文件继续使用已有 Artifact。需要预览的资源由宿主授权读取后传递，限制类型、大小和生命周期，不向 HTML 开放对象存储地址。首版不支持用户任意导入第三方脚本。

## 4. 受限页面 SDK

以下为目标能力名，最终 Schema/TS 在 P9-00 固定。AI 使用平台提供的真实接口说明，不自己编写认证或请求协议。

| 能力 | 行为与边界 |
| --- | --- |
| `getContext()` | 返回绑定契约、运行/预览/历史模式、主题/语言与最小用户显示信息，不返回令牌或人员目录 |
| `invoke(input, options)` | 通过正式应用入口创建 Invocation；请求键/发布修订由可信宿主管理，不接受 applicationId 或任意 URL |
| `getTask(taskId)` / `subscribeTask(taskId, cursor)` | 按授权恢复状态、结果和全部可见待办；订阅断线通过持久查询校准 |
| `listMyTasks(query)` | 限当前应用与本人、有界分页；读取旧任务前由宿主加载其原页面版本 |
| `submitTaskInput(taskId, waitId, content)` | 绑定等待修订和请求键，所有入口执行同一 responseSchema 校验 |
| `cancelTask(taskId)` | 返回正式取消受理与后续状态，不提前显示终态 |
| `uploadFile(file)` / `downloadFile(taskId, fileRef)` | 复用 Artifact 归属、类型/大小/Hash 与下载检查，不读任意路径/URL |
| 会话绑定的输入/消息 | 在应用声明的 Session/ChatMapping 下使用正式入口，不能由 HTML 填写可信 userId |
| `openApproval(approvalId)` | 由可信宿主验证后打开现有审批中心；不向页面提供批准/拒绝能力 |

Bridge 每次只代理明确动作，不提供通用 `fetch`、代理请求、管理 API 或凭据读取。客户端字段校验改善体验，服务端正式 Schema/权限校验仍为权威。SDK 对规范错误保留 code/fieldErrors，AI 不把失败包装成成功。

创建任务的稳定 requestId 在提交前产生并在网络重试中复用。用户调整后重新生成是新的请求及关联调用；不能用同一键更换参数。页面不得在加载、重绘或预览时自动提交业务操作。

## 5. 登录、授权与独立业务外壳

`/a/{slug}` 是受保护的独立路由，复用 AuthProvider 和现有登录流程，不放在挂载管理侧栏的 EnterpriseLayout 内。可信外壳显示应用、当前用户、退出和必要平台状态；AI 不生成账号密码表单。

1. 未登录跳转现有登录页，并只接受校验后的站内返回路径。
2. 登录后按应用使用权限及对象范围加载发布物；只有使用权的员工不需要 `application:view`、工作流编辑或 Trace 权限。
3. 任务、事件流、等待、会话、文件及取消均继续检查真实用户和应用归属；页面入口检查不能替代后端授权。
4. 登录过期由可信宿主管理续期/重新登录。退出、换账号或撤权时销毁 Bridge、清空业务内容/内存并终止订阅，不让旧端口继续操作。

不另建员工账号系统。页面 source 中的用户标识、客户标识和应用名称都不能成为可信身份。Web 登录和 MCP OAuth 是独立接入能力。

## 6. 后缀与路由约束

首版固定前缀 `/a/`，管理员仅配置一个规范化 slug，例如 `sales-quote`。作用域按当前部署的租户/站点确定；数据库唯一索引与前置检查共用规范化规则，冲突返回 409/fieldErrors。生成 Agent 不设置或修改后缀。

禁止任意根路径、嵌套路径、编码分隔符、`..` 和与保留路由冲突的形式；不新增任意域名、DNS 或 TLS 管理。更换后缀是显式配置发布，旧地址停止使用，不保留别名或跳转兼容层。

HTML 不能自行生成跳转地址。任务、审批、文件等导航由宿主按受控引用打开；查询参数里的 taskId 仍需完整授权。

## 7. 隔离宿主与预览

AI 生成的脚本按非可信内容处理。基线使用仅开放必要脚本能力的 sandbox iframe，不授予 `allow-same-origin`、顶层导航、弹窗等权限；不得将 HTML 直接注入有管理权限的同源 DOM。

实现采用两层 opaque iframe：控制层和生成层均以 `srcdoc` 交付，可信控制层以 `frame-src about:` 限制生成页自身导航，生成层以 `frame-src 'none'` 禁止子框架。两层仅开放 `allow-scripts allow-forms`；真实浏览器证明若不开放表单，浏览器连被 JavaScript 接管的 submit 事件也会阻止。两层都强制 `form-action 'none'`，因此允许表单校验和事件，不允许网络表单提交；相关外发测试必须在此正式配置下通过。凭据只留在外层可信宿主。

2026-11-02 本地升级联调发现首次导航时生成层已设置 Blob URL，但实际文档仍停在 `about:blank`，产生 `PAGE_HANDSHAKE_TIMEOUT`；创作中后续更新可掩盖此问题。改用标准 `srcdoc`，消除 Blob 注册和导航生命周期依赖；每次 Host 绑定创建独立且已填充的控制层 iframe。双层不透明 Origin、CSP、私有 MessagePort、撤权及业务权限边界保持一致，HTML/SDK/业务 Bundle 仍按原发布清单固定。`sandbox` 未开放 `allow-same-origin` 的隔离语义见 [HTML 标准](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)。此修正的本地证据单独记录，不改写此前验收轮次的源码身份和原始结果。

平台强制 CSP 和资源策略，限制连接、表单外发、子框架、对象、基址和外部脚本；生成内容不能放宽。所有业务网络和文件访问都通过宿主 SDK。iframe 自身导航、meta refresh、外链及 URL 型样式/资源也纳入发布检查与浏览器验证；不能仅靠 `connect-src` 宣称完全阻断外发。

握手绑定确切 iframe Window、一次性随机挑战、当前账号、应用、页面版本与运行模式，再传递独立 MessageChannel。opaque origin 的 `null` 不能作为信任条件；消息按方法/参数 Schema 校验，有 requestId、大小/并发/超时限制。重载、导航、发布切换或登出后关闭旧通道，拒绝迟到请求。

可信 SPA 外壳响应同时设置 `Cross-Origin-Opener-Policy: same-origin` 和 `X-Frame-Options: DENY`。正式入口是独立顶层页面：前者隔离站外打开者持有的 Window 引用，后者禁止站外页面嵌入整个可信外壳；外壳内部的两层 opaque iframe 继续使用既有配置。实际浏览器反例证明，仅限制生成层资源请求仍不能阻止其向保留引用的站外打开者转发 SDK 返回值，因此这两项属于交付边界。依据：[COOP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cross-Origin-Opener-Policy)、[X-Frame-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options)。

预览只提供合成数据和内存交互，Host 硬拒绝业务写入/真实上传和生产凭据访问；明确标注模拟。用户在可信工具栏发起实际测试时创建独立测试运行上下文，显示目标部署及潜在业务动作，生成 Agent 无权切换为实际模式。真实联调记录 Invocation 和来源，不以预览截图冒充正式通过。

预览在处理 `invoke.input` 和 `submitTaskInput.content` 时，按冻结输入 Schema 和当前待办 responseSchema 校验实际页面载荷，失败不会创建任务、消费待办或增加成功计数。使用固定 `@cfworker/json-schema 4.1.4` 的解释执行校验器，保持 CSP 不允许动态 eval/Function，不获取外部 Schema；正式 Runtime 仍为权威。依据：[库的能力与已知边界](https://github.com/cfworker/cfworker/tree/main/packages/json-schema)。JSON Pointer 仅标识字段位置，不能把 `/contact` 当成对象属性 `contact` 的替代键。

合成任务也先返回 accepted，再异步产生等待或完成状态；页面必须实际订阅或查询原任务的更新，不能只显示提交回执就通过检查。数组在契约允许时至少填两行，字段路径必须在增删后立即更新，删除操作绑定具体行。文件控件绑定 Artifact 字段本身，检查不要求员工输入文件内部元数据。缺少业务字段或标记时返回明确诊断，交给页面 Agent 修复；这些合成检查仍不替代正式工作流执行。

模拟订阅只在任务修订变化时通知，避免无变化的定时通知反复重绘并清空正在填写的补充表单。输入标签在提交前检查，不能把提交后已卸载的表单误报为无标签。平台检查器修复后的原页面复核保留原 HTML/修订/创作 Run 和全部首次失败，仍需两组正式业务执行才计为通过，不额外增加 AI 修复轮次。

每次静态或交互检查从新的隔离页面和空的合成任务状态开始，同一编辑器内的检查按顺序执行。先撤销旧端口并终止旧检查，再清除模拟任务、订阅与计时器，使用新绑定完成握手后检查原 HTML；不更改源码、修订或契约，不触碰正式任务。这样支持提交后切换到任务视图的合法页面，重复检查不会把上一场景已经收起的初始表单误判为缺失。旧握手不能恢复新端口，离开编辑器必须结束尚未完成的重置等待。

合成数值在契约允许时包含小数，保留整数及 multipleOf 限制。检查记录浏览器原生校验消息，提前发现页面把合法小数限制成整数等错误；等待输入诊断注明对应 waitId/nodePath，字段路径相对于该等待的 responseSchema。原页面已经用尽三次实际 AI 创作/修复仍失败时，保留失败，不追加第四次或人工修改源码。

完整矩阵必须覆盖原定 64 份真实生成页面，不能重新随机生成页面替换已经失败的样本。已证实的平台检查器误判可以复核原页面：原始 HTML 字节、修订、创作 Session/Run 和失败报告保持不变；修复后重新执行完整检查、正式发布、两组未参与生成的业务输入及相关恢复流程，不增加一次 AI 创作。若修改严格限于私有检查器，必须通过精确字节差异和冻结源码 Hash 证明 SDK 公共能力、授权、契约、业务执行、审批与 MCP 均未改变，并通过当前代码的完整检查、隔离回归及受影响系统回归；影响范围外的原矩阵证据保留原 SDK/发布绑定，通过单独的合并审计核对。原失败记录不回填成功，新交付绑定与原生成来源分别记录。不能证明上述边界，或业务逻辑也发生变化时，重跑受影响的正式业务验收；缺失或失败继续保留为未完成。

契约工具同时返回由 Rust `TaskViewV1` 生成的权威任务 Schema；`allowedActions` 是带 `canCancel` 等字段的对象，不能让生成器猜成动作数组。预览报告保留不超过 8000 字符的可见页面文字，用于诊断页面自行捕获并显示的异常；点击过程中新增的未捕获异常也纳入本次检查。该文字是合成预览数据，不能作为系统指令，不增加业务调用或权限。

检查报告由 Rust DTO、OpenAPI 和生成的 TypeScript 类型共同约束，网页使用生成类型而不再手写整份报告结构。`diagnosticText` 在正式记录接口中必填、限长并持久化；只在浏览器增加字段而未同步服务端时，类型检查必须报错，不能等真实模型验收才发现接口漂移。

浏览器隔离依据：[iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[postMessage 的来源与消息检查](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)、[MessageChannel](https://developer.mozilla.org/en-US/docs/Web/API/MessageChannel)、[CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)。D9-07 必须实测导航/外发与端口能力边界；无法满足时保持未通过，不扩大权限来运行页面。

## 8. 草稿、发布与历史任务

- 一个应用维护当前工作 HTML；创建接口在应用锁内复用已有页面，重复进入不能生成第二份工作内容。AI 编辑走修订/Hash 校验、差异和自动保存链，过期命令返回冲突，不覆盖新编辑。聊天按当前 HTML 与本人绑定，窗口重新打开可接续；新的编辑窗口接管绑定时旧窗口的写入被拒绝。
- 静态报告、隔离交互报告和用户测试证据绑定精确 HTML/契约/SDK/Bundle；修改后旧报告失效。发布至少要求静态/隔离检查通过；实际联调证据单独显示，不能标成静态校验已证明业务正确。
- 发布产生不可变 UI Version 和 Publication，固定 HTML、完整契约、SDK/样式和 Bundle；通过现有 prepare/activate 复制到 Runtime。所有物料核验完成后原子激活，失败不暴露部分新发布。
- 工作流升级不自动改变页面绑定。相同契约也要显式验证并发布新组合；契约改变须调整页面。无页面修改也不能只凭 Hash 相同就宣布业务语义已验证。
- 页面提交携带 Publication 的预期修订；激活切换后旧页面新提交返回明确冲突，保留用户输入并提示刷新，不悄悄执行其他 Bundle。
- Web 任务固定创建时 UI Version；从“本人记录”或任务链接打开时先由宿主切换原 UI，再注入授权 TaskView。原发布仍是启用中的当前版本时保持正式运行模式，声明过的会话可在刷新后继续使用原 Session。只有原发布已被替换或入口已停用时进入历史模式；历史模式不能新建旧版本任务，补充信息/取消仍针对原任务；重新生成回到当前正式发布。
- MCP 任务只在有匹配其 Bundle 的发布页时提供任务链接，打开不改变其原来源/版本。没有页面时 MCP 本身仍可独立使用。
- HTML、SDK/样式和引用文件受任务/未结算 Effect 的 Retention 保护。回退是显式激活已有完整组合；不改写工作 HTML、创作会话或已运行任务，也不为旧 SDK 保留另一套兼容实现。历史预览仅用对应冻结物料和合成数据，不执行正式业务。

发布后运行物料从 Runtime 本域读取，Control 短时不可用不影响已发布页面的既有业务调用。HTML 或 SDK 缺失/Hash 不符时明确失败，不能临时让模型补页或换用最新页面。

## 9. 实现落点与验收

Control：应用页面草稿/版本/后缀/发布模块、对象权限、设计态工具及签名包。Runtime：发布物接收/读取、页面绑定 Admission、共享任务/会话/Artifact 服务。Web：应用 Tab、生成面板、独立业务外壳、隔离宿主与共享 SDK；保持模块化，不继续扩大应用详情大文件。

数据结构改初始化 DDL，使用所属域 Artifact/引用保护；自动化沿用 Python pytest 与 TypeScript Playwright。主交付 P9-02/P9-03；验收 E9-G01–G08、E9-W01–W12 和 E9-X01–X04，详见 [验收矩阵](05-e2e-acceptance.md)。
