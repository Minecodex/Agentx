# 应用界面的持续编辑、发布与历史

2026-11-02，按用户要求把“访问界面”收敛为一个工作 HTML 和右侧持续聊天，删除顶部生成卡片、草稿选择和独立发布配置卡片。设计规则见[应用网页设计](../03-application-web-ui.md)。

## 交互结果

- 进入应用后自动打开当前工作页面；首次创建只准备编辑目标，不自动消耗模型调用。
- 用户在右侧描述需求，AI 通过原有工具读取、修改、检查并自动保存同一 HTML。重新进入或关闭后重开，恢复该页面与本人的同一段聊天。
- “HTML 源码”只读；页面修改通过聊天提出。差异和检查仍可查看，界面不显示草稿选择或编辑版本。
- 首次点击发布弹框填写 `/a/` 地址后缀；后续点击沿用当前地址。发布先完成静态和模拟检查，再走原有不可变物料准备与原子激活。
- “发布历史”独立展示当时冻结的 HTML、SDK、样式和契约，并以合成数据预览。回滚只切换线上完整发布，不改工作 HTML、不清空或切换聊天、不新建编辑内容。删除原恢复为草稿接口。
- 工作页面创建在应用行锁内复用，重复进入不会创建第二份页面。本人聊天按页面复用；新窗口接管时通过修订和绑定隔离旧窗口写入，保留原消息与 Agent 状态。
- 编辑区适配桌面高度，1440×900 和 1280×720 下聊天输入与发送按钮均可见。预览在 iframe 内滚动；历史流中的增量片段不产生空消息行。开发模式重复挂载共享一次绑定请求，避免重复接管造成修订冲突。
