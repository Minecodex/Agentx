# Agent 具体工具调用审批

状态：complete。对应讨论第 4 项，P9-04 已实现；具体 Effect 的批准、拒绝重提、并发决定、撤权、换 Worker 和未知写入不重放均取得实际证据，见 [最终报告](evidence/2026-11-02-acceptance.md)。扩展现有审批中心，不增加工具审批菜单；现有审批节点和设计期资源授权申请不能直接替代本方案。

## 1. 审批对象与策略

在 Agent 运行过程中，对一个已经产生且参数确定的 MCP Tool 调用发起审批。首版在工具资源上配置是否需要审批、指定成员或角色及超时，Agent 面板展示实际生效规则。发布时将工具版本与审批策略固化进业务包，运行时仍检查授权和策略撤销。

审批针对实际操作，不以模型自报的“高风险/低风险”作为执行开关，也不把 MCP Server 提供的 Annotation 当作可信授权政策。

| 已有/新增对象 | 含义 | 目标动作 |
| --- | --- | --- |
| 资源授权申请 | 允许 Workflow 使用某资源 | 创建资源 Grant |
| 工作流审批节点 | 流程预设位置的人工决定 | 恢复指定节点分支 |
| `await_input` | 提交业务信息 | 接收 content 并继续原流程 |
| 工具 Effect 审批 | 同意一次明确工具操作 | 允许执行绑定的原 Tool Effect |

工具审批纳入既有运行审批中心和权限投影，增加明确的对象类型和恢复目标，不把四种行为合为一个无类型 JSON 入口。

## 2. 审批卡片

现有审批中心的可信卡片展示任务用途、操作对象、工具名称、真实参数、相关材料、批准/拒绝按钮和意见。原值/新值只有在可信业务查询或工具契约提供时才展示，不能由模型摘要伪造。

敏感字段按统一策略脱敏，审批人取得作决定所需的有限材料；不自动开放全部 Trace、其他客户信息或 Credential。LLM 摘要是辅助阅读，底层批准依据始终是已校验的真实调用。

首版批准或拒绝时均提交预期审批版本与幂等键。编辑参数需要形成新提案、重新校验并重新审批；旧提案及决定不可覆盖。

AI 生成的业务 HTML 只获得等待摘要和指向审批中心的受控入口。页面 SDK 不提供批准/拒绝接口；登录员工、页面管理员或生成 Agent 不因其身份自动成为审批人。审批决定由现有可信页面重新认证并校验当前资格，不由生成页面传入一个 approved 字段代替。

## 3. 具体调用绑定

审批快照至少绑定：

- tenant/application/invocation、execution/nodeExecution、实际 Bundle 和调用者快照。
- agentRunId、operationId、原 toolCallId、effectId 和工具资源/版本。
- 规范化实际参数及 Hash、审批策略版本/Hash、来源和必要业务前置条件。
- 审批对象版本、候选成员/角色、deadline、决定人、决定、原因及恢复回执。

批准凭据只对这一组身份和参数有效，不能复用于同名工具的新调用。租约/Fencing 是恢复时的执行所有权验证，不应因更换 Worker 迫使业务参数和批准记录变为另一次操作。

业务目标支持版本号/ETag 时，在实际写入前复核；对象已变更则旧提案失效，交由 Agent 重新查询并生成新提案。工具不提供条件写能力时，不宣称已实现远端事务隔离。

## 4. 挂起与恢复

```text
Agent 产生 Tool Call
  → 校验参数、当前 Grant 和冻结工具/策略
  → 持久化 Operation Intent、检查点、工具审批及通知 Outbox
  → Pending，保存原调用栈/操作状态并释放 Worker 执行槽
  → 平台审批人批准或拒绝
  → Runtime 持久化唯一决定与恢复命令
      ├─ 批准：复核权限/策略/取消及业务条件 → 执行原 Effect
      └─ 拒绝：不发出外部调用 → 结算结构化拒绝结果
  → 原 Core Operation 消费一次真实结果，继续原 Agent
```

Core 只表达通用 Pending/Resume 和工具结果；Runtime Adapter 管理审批、SQL、通知和执行权限。不能从最初 Prompt 重新启动 Agent，不能用新 Attempt 身份掩盖前序写入。

实现审计补充（2026-11-01，待实际恢复验收）：现有 Runtime 的普通 Agent Session 排队使用 `retry_waiting` 创建新 Attempt，Worker 回执以 Attempt 为唯一键；这条路径不能承载具体 Effect 审批。工具审批增加原操作继续命令：保持 Attempt/AgentRun/Operation/Effect/参数 Hash 不变，恢复同一机器激活，只创建新的派发消息和租约轮次。Attempt 保存当前派发 taskId，拒绝审批前的旧队列消息；Worker 回执以 `(attemptId, fencingToken)` 为唯一身份，旧轮回执只重放旧轮结果。所有租约仍检查当前 Fencing，不给旧 Worker 写入能力。

审批任务与 Effect 映射在已持久化 Core Intent 后幂等创建；即使在 Core 写入 Pending 前强退，恢复也只能观测原审批，不能先执行工具。协调器等待原 Attempt 的 Suspended 事实后，才按唯一决定写入继续命令，覆盖“人已决定、Worker 尚未提交挂起”的竞争。节点并发槽在挂起时释放；Token/费用预算与累计账本保留，恢复不重置。审批 wall-clock deadline 与活跃执行剩余时长分开，恢复只延续原剩余活跃时间；Workspace/STDIO 仍按自身 TTL 校验。

审批创建、Core 状态与恢复命令的提交边界必须在 P9-00 实测：使用同一 Runtime 事务，或由已持久 Intent 幂等补齐；任何可恢复中间状态都不能提前调用工具。现有 `ToolPortError::Pending` 只是接口基础，不替代这项实现。

批准后再次验证当前 Grant、Credential、资源/策略有效性和审批资格；已撤权、取消或过期的调用不能因为曾被批准而执行。批准决定只允许继续操作，不提供新的资源权限。

恢复时先读取原 Effect 与 Provider 账本：已持久化的成功、确定失败和结果未知都是业务事实，不因后续撤权被改写。读取回执不发起新工具调用；只有明确尚未发出的操作才进入当前授权复核。HTTP 工具已结算但 Core 尚未收取时从原回执结算，已外发但没有可靠结果时保留结果未知。STDIO 已派发帧缺少可确认结果时同样禁止重新写入。

## 5. 拒绝、超时与并行

拒绝结果以明确结构交回模型，包含拒绝原因及允许说明的业务意见。Agent 可以解释、降低报价折扣或提出其他方案；同一参数的重复提案受到已有重复调用/预算限制，不能无限刷审批。

审批超时与拒绝分别记录，具体工具调用均不执行；是否继续 Agent 由冻结的工作流错误/终止策略决定，不伪装成模型正常成功。取消使未执行的审批失效，并通过现有持久取消链路传播。

一个模型回复包含多个工具调用时，每项审批分别绑定原 toolCallId/effectId；按 Core 正式调度规则继续，不因为一项获批就执行同轮全部调用。审批决定竞争使用行锁/预期版本/幂等，终态不得被其他决定覆盖。

等待审批不占用 Worker 线程或 Attempt 执行槽。Agent 的活跃执行时长、审批 wall-clock deadline、会话顺序和原累计 Token/成本预算分别定义；等待不能重置预算或无限延长 Sandbox TTL。

Workspace/STDIO 按现有 TTL 管理，不能为人工等待无限续租。恢复所需资源已失效且无法按既有协议安全恢复时，明确收敛为资源/恢复错误，不重放此前文件操作或工具写入。具体租约和恢复规则属于 D9-04 的前置验证。

## 6. 外部副作用与结果未知

| 故障/竞争 | 必须行为 |
| --- | --- |
| 创建审批或决定时强退 | 原 Intent/决定可查，通知和恢复命令幂等补齐 |
| 决定后 Worker 更换 | 新 Worker 校验 Fencing，继续同一 Effect，不创建第二次批准 |
| 批准后、调用前撤权或取消 | 拒绝执行，保留决定与真实失败原因 |
| 工具已返回，Core 结算前强退 | 读取既有 Receipt，模型只消费一次结果 |
| 写入已发出但没有响应 | 按现有 Ledger/OutcomeUnknown 核实，不以批准为由盲重试 |
| 两人同时决定、迟到按钮或通知 | 返回原决定或版本冲突，终态不改写 |

审批不保证外部系统 exactly-once。只有 Provider 的正式幂等/查询协议和现有执行账本能支持相应重放或对账；无法证明结果时保持“待核实”。

工具审批的保证只覆盖受控能力。发布校验必须识别并约束同一 Agent 中能通过 Bash/HTTP/其他工具访问相同业务写凭据与目标的绕行路径；不能在仍开放等价写路径时宣称所有相关写入必经审批。首版不尝试通过自然语言理解任意 Shell 命令来判定具体业务操作。

## 7. 数据与实现落点

扩展 Runtime `approval_tasks` 的对象联合及索引，关联既有 Agent Operation/Effect/账本；Control 投影携带相同类型与脱敏摘要。既有节点审批分支与工具审批恢复命令明确区分，不为工具审批伪造一个审批节点。

策略配置进入 Control 资源修订与 Bundle；Runtime 在 `worker_runtime_agent_core.rs` 等 Adapter 的权限/执行边界接入；Web 复用审批中心和任务待办卡片，按类型拆分具体内容组件。Core 保持零基础设施依赖，避免继续扩大已接近行数上限的适配器文件。

主交付任务为 P9-04；验收编号 E9-A01–A08、E9-X01–X04，详见 [验收矩阵](05-e2e-acceptance.md)。

资格投影补充：Runtime 的最小用户投影显式携带当前 `canApprove`，与成员/角色候选匹配共同生效。审批决定后再次执行时仍检查这一资格，避免只验证“仍在某角色”而遗漏该角色的审批权限已被撤销。平台模型和业务模型不提供这一授权事实。
