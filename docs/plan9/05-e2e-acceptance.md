# plan9 验收与证据

状态：complete。以下 38 项要求已逐项评审通过，实际结果、原始失败和复测证据见 [最终报告](evidence/2026-11-02-acceptance.md)；历史过程见 [实施记录](08-implementation-evidence.md)。以生成的实际 HTML 和正式业务调用验收，静态 Demo 不构成功能证据。

## 1. 统一环境与分工

沿用 [Kubernetes E2E 规范](../plan/e2e-testing-standard.md)，系统唯一编排入口为 `uv run --frozen --group test pytest tests/e2e`。Python 复用现有 fixture/agentxctl 管理临时环境、进程、证据和清理；业务浏览器操作由 `tests/browser` 的 TypeScript Playwright 完成。

临时 Control/Runtime/Dependencies 等 Namespace、入口和数据域按现有 fixture 创建。资源不足时使用已有 `--scale-down-development` 记录并缩容开发服务；成功或失败都在 finally 恢复原副本、停止端口转发/子进程并卸载临时资源。不建立 plan9 专属测试框架，不复制 Rust 部署逻辑或新增 PowerShell/Batch。

## 2. 分层检查

| 层 | 主要检查 |
| --- | --- |
| Core/Host | 同一 Core/恢复驱动、Profile 工具边界、目标联合、压缩、取消与预算 |
| 契约/边界 | Rust/OpenAPI/Schema/TS、来源 CHECK/索引、模型授权、页面/Bundle/SDK 快照 |
| 页面宿主 | 登录、iframe/CSP、Bridge、发布修订、任务/文件授权、预览与实际模式 |
| Runtime | 幂等/取消/等待、Pending/Resume、Lease/Fencing、Receipt、撤权和 OutcomeUnknown |
| Web | 应用两个 Tab、独立业务外壳、实际生成页、现有审批中心、桌面主题/语言/键盘 |
| 系统 | 正式 API/UI/MCP、临时集群、重启/竞争、真实模型/客户端与业务写入次数 |

测试验证行为和不变量，不为文案修改编写镜像实现的测试。没有新变化、失败或疑点时不反复扩大检查；阶段完成仍须执行规定系统回归。

## 3. 共用设计态 Agent 与网页生成

| ID | 必须通过的场景 |
| --- | --- |
| E9-G01 | 网页与工作流使用同一平台 AI 选中模型；无网页独立选择器；冻结 Run 后普通切换只影响新 Run，撤销/凭据失效停止后续调用 |
| E9-G02 | 同一 Core/Host 驱动两种 Profile、压缩/steering/恢复；Session/目标隔离且共用租户并发池，不创建业务 Execution/Attempt |
| E9-G03 | 网页读取权威契约并用 page_edit/page_check 完成初稿；无额外需求也有输入、提交、状态、结果；工作流原七工具回归通过 |
| E9-G04 | 用户自然语言调整布局/字段/结果后，生成的 HTML 在模拟 SDK 下完成真实点击、字段校验、文件状态和错误反馈，控制台无阻断错误；不能用预先手写成品冒充 AI 输出 |
| E9-G05 | 人工编辑竞争、过期 Hash、草稿切换、编辑 ACK 丢失与保存失败，不能覆盖新内容/跨目标投递；报告绑定精确源码和契约 |
| E9-G06 | HTML 注释/样例提示注入、伪造 Profile/tenant/actor/target、未知工具均拒绝；AI 不能运行业务、批准、授权、切换模型或发布 |
| E9-G07 | 模型结算/Host 强退、停止/撤权/Fencing 变化、输出截断、重复错误，恢复原 Effect，Usage/Entry 不重复，未完成页面不标成功 |
| E9-G08 | 两种来源目标在签名、Runtime 账本/Quota/Artifact/Retention 中一致；不伪造 Workflow ID，不混入业务成本，预览不增加业务/Provider 写入计数 |

真实模型至少生成报价应用页面并按需求修改一次，保存提示词/Profile/模型版本、脱敏调用标识、原始生成 HTML Hash、检查报告和浏览器证据。Fixture 用于确定性注入边界，不能替代这一项。

## 4. AI 应用页面与发布

| ID | 必须通过的场景 |

| E9-W04 | 本人历史、刷新重开/SSE 重连、跨员工/应用/租户/服务主体反例；读/写/文件授权一致，内部 Trace/凭据不可见 |
| E9-W05 | 结构化与原始 JSON 等待、子流程/并行等待、重复/迟到输入及取消/超时竞争；原输出和人工输入各自保留 |
| E9-W06 | 按应用声明的 Session/ChatMapping 提供对话交互，初始参数/真实用户/任务不串；未声明的交互不能凭页面代码启用 |
| E9-W07 | iframe 不能读宿主 Token/DOM/存储；验证网络/资源/表单/自身与顶层导航、meta refresh、外链、弹窗等绕行，CSP 不能被生成内容放宽 |
| E9-W08 | 伪造 Window/null origin、跨页面/账号端口、未知方法、超限消息、重载与迟到请求均拒绝；预览硬拒绝实际任务/上传及审批 |
| E9-W09 | 后缀规范化与并发唯一性、非法路径、发布前访问、改后缀旧址停用；冲突返回稳定 409/fieldErrors |
| E9-W10 | HTML/SDK/契约/Bundle Hash 检查、准备失败/激活强退、并发发布/回退及缓存；不存在混搭版本，旧页面提交得到明确修订冲突 |
| E9-W11 | 历史任务加载原 UI/Bundle，历史模式不新建旧任务；停用入口不隐式取消；权限撤销/登出/换号销毁端口并清空内容，旧资源受引用保护 |
| E9-W12 | 桌面 1440×900，中英文与浅深主题、键盘/基础控件、真实按钮；认证过期/重新登录、部分故障及错误状态清晰，无管理侧栏 |

所有隔离场景同时覆盖管理预览和正式业务宿主；以浏览器实际请求和服务端计数断言，不能仅检索源码中的禁用字符串。隔离未通过时保持门禁失败，不通过扩大 iframe 权限绕过。

## 8. 证据与完成判定

证据写入 `.local/artifacts/e2e/<run-id>/` 及规范中的 Playwright 目录，包括命令、源码/镜像身份、用例编号、生成/任务/审批标识、HTML/SDK/契约/Bundle Hash、断言、截图、请求记录、失败复测和清理结果；写盘前脱敏凭据及真实业务数据。

实际汇总已写入 [验收报告](evidence/2026-11-02-acceptance.md)，P9-00–06 按对应证据关闭。原始失败的 JUnit、生成页和损坏记录保留，复核结果单独关联，不回填原记录。后续外部条件不足时仍须记录未执行与原因，不能以 skipped 替代门禁；既有生产容量/强隔离缺口由原计划继续跟踪。
