# 应用发布为 MCP 工具

状态：complete。对应讨论第 2 项，P9-05 已实现；20 类应用协议、8 类独立 OpenCode 调用与真实个人 OAuth 登录、刷新和撤销通过。原始调用和边界证据见 [最终报告](evidence/2026-11-02-acceptance.md)。

## 1. 产品流程

1. 尚无发布时，应用“MCP 接入”Tab 仅展示发布按钮；点击后弹框填写工具名称、访问后缀。描述默认使用应用说明，可在弹框调整；业务版本使用应用当前正式部署，多正式环境时在弹框明确选择。
2. 发布后主界面展示接入文档、地址、输入输出和连接配置，右上角提供“更改发布”和“发布历史”。更改发布仅编辑工具名称、后缀、描述，绑定同一环境当前正式业务版本并创建新的不可变发布。
3. 历史弹框列出每条发布的名称、后缀、描述、版本、时间和同步状态，可查看该条接入文档、删除该条发布。新发布不替换旧发布；管理员自行删除不再兼容的版本。
4. 获准用户在 MCP 客户端完成授权，发现该应用业务工具。
5. 客户端提交任务、查询状态，在必要时补充信息，最后取得结构化结果与授权文件引用。

删除一条发布只撤回该条工具与后缀绑定；已有任务是否取消必须由单独明确动作决定。删除最后一条发布后，该后缀停止提供 MCP 服务；既有任务仍按原归属保留，可通过其他仍有效的应用入口或正式任务 API 访问。禁止删除发布时隐式重算、删除或重跑既有任务。

Web 页面与 MCP 可分别发布，MCP 接入不要求先生成 HTML。“访问界面”Tab 管理网页，“MCP 接入”Tab 管理协议与认证；两者复用同一应用、任务和业务 Runtime。网页已登录不代表 MCP 客户端已完成 OAuth。

## 2. 发布与工具模型

每条发布保留独立的工具名称、访问后缀及业务 Bundle。正式路由为 `/gateway/v1/mcp/applications/{slug}`；同一应用可以保留多个后缀，同一后缀可以包含该应用多次发布的不同业务工具。每个后缀提供仍保留的业务提交工具及以下公共工具：

| 工具 | 输入 | 行为 |
| --- | --- | --- |
| 管理员命名的业务工具，如 `prepare_customer_quote` | `requestId` 和由工作流契约生成的 `input` | 创建或复用 Invocation，返回统一任务结果 |
| `get_task` | taskId | 返回授权后的状态、可见待办、最终输出/错误与文件 |
| `submit_task_input` | taskId、waitId、requestId、content | 调用正式输入恢复服务，提交原始业务信息 |
| `cancel_task` | taskId、requestId | 发出取消命令，返回权威受理及后续查询方式 |

业务工具名不能与公共工具重名。工具说明必须区分“提交任务”和“已完成业务”；公共查询/取消/输入工具也检查当前主体权限，taskId、waitId 和 MCP Session ID 都不是授权凭据。

输入 Schema 自动包裹为 `requestId + input`，不重新手工定义业务字段。输出使用稳定任务外层结构，例如：

```json
{
  "taskId": "<invocation-id>",
  "state": "waiting_approval",
  "taskUrl": "https://<web-origin>/a/<slug>?taskId=<invocation-id>",
  "pendingInputs": [],
  "pendingApprovals": [{ "title": "确认写入客户报价" }],
  "result": null,
  "files": [],
  "error": null
}
```

字段名、状态枚举和错误码由 P9-00 冻结后生成 Schema/TS。待审批摘要只说明当前业务状态，不包含批准能力或未授权材料；审批决定必须通过正式审批链路。

taskUrl 可空，仅在存在与本任务实际 Bundle 匹配的可用页面且当前主体可访问时返回；链接不携带令牌。打开后由可信宿主登录、校验归属并加载匹配页面，不把当前最新页面直接套在旧任务上。没有页面时 get_task 等能力保持完整，不临时生成网页或增加全局任务菜单。

## 3. 长任务与重复请求

- 业务调用统一返回上述任务结构；已完成时提供结果，尚未完成时返回真实状态和查询入口。
- HTTP/MCP 请求断线不自动取消持久任务，客户端使用同一 taskId 重新查询。
- 创建使用客户端明确指定且尚未删除的发布 Bundle；同一幂等请求重投仍指向原 Invocation，不因新增发布创建新任务。
- 幂等范围包含租户、应用、真实调用主体、操作和 requestId；同键不同输入 Hash 返回冲突。
- JSON-RPC 请求 ID、模型生成的工具调用 ID 和相同业务参数均不能替代显式业务幂等键。
- 配额、并发、取消和保留复用现有 Runtime；请求受理与最终业务结算分别展示。

提交/查询工具是长期稳定的业务任务接口，不伪装成 MCP Tasks 扩展。[MCP Tasks](https://modelcontextprotocol.io/extensions/tasks/overview) 的客户端支持需单独验证，本计划不依赖未经验证的扩展能力。

## 4. 授权与真实用户

正式方案支持两类主体：个人客户端通过标准 OAuth 映射平台用户；服务集成使用应用范围的现有 API Key。分别记录客户端授权、实际调用主体和运行身份，不能因为来自同一应用就互相读取任务。

OAuth 需要成熟授权服务/实现、资源服务器验证、客户端和应用范围、用户映射、授权查看/撤销及 Token 生命周期。P9-00 先完成选型和真实客户端握手；若已有 `rmcp` 无法满足选定协议，显式升级固定依赖，不手写整套 MCP/OAuth 协议或保留旧协议双入口。

Token 必须通过受支持的认证通道传递，不嵌入 URL、工具参数、模型上下文或日志。Origin/Host/会话隔离、代理转发和发现端点按实际固定规范验证。参考 [MCP HTTP 授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)。

调用者的权限只允许使用应用与查看自己的任务，Model/MCP/Credential 等仍按 Workflow Service Identity 的签名包和当前 Admission 执行。任务查询、SSE、取消、补充信息与下载不得采用不同的归属判断。

## 5. 文件与结果

输入文件复用正式 Artifact 上传与归属校验，工具只接受授权引用。本机路径、任意 URL 和外部 MCP resource URI 不自动转换为本地 Artifact；文件型客户端需验证其实际上传集成，不能宣传所有客户端都能直接传文件。

输出只开放调用结果明确引用的 Artifact，使用同一应用/任务授权下载，继续核验大小和 SHA-256。任务链接不携带 Token；私人 Trace、内部工具结果、Credential 和 Sandbox 文件不因 MCP 发布而开放。

## 6. 发布、回滚与边界

- MCP 接入修订绑定部署的完整输入/输出契约及业务说明，通过现有发布投递进入 Runtime。
- 工具发现返回当前后缀下未删除的全部业务工具；同名工具以最新保留修订展示 Schema，客户端通过 `publicationRevision` 仍可调用未删除的旧修订。不同后缀不能借传入别的修订调用彼此的工具。
- 删除经原 Publisher Outbox 投递为精确 publicationId 的撤回，完成后仅该发布停止新提交。最后一条删除后入口和 OAuth 资源发现不再可用；新发布不自动撤销其他发布。既有 Invocation、审批、Artifact 与原绑定保留，不取消或重算任务。
- 发布内容保留不可变，删除保留审计墓碑；不通过物理删除历史 Manifest 破坏任务追溯。最后一条删除确认后释放后缀占用。
- 每次调用保存实际配置修订、Bundle、主体与来源，历史结果按原快照读取；部署回滚同样产生可追踪的生效切换。
- 企业内桌面/CLI 客户端与云端客户端分别验收。云端可达地址、TLS 和 OAuth 条件不具备时，该客户端保持未验收。
- 不发布画布编辑、版本创建、资源授权或应用部署工具；外部 Agent 只能调用管理员开放的业务入口。

## 7. 实现落点与验收

Control 增加应用 MCP 配置/修订、授权管理与发布校验；Runtime Gateway 增加独立 MCP 适配模块，调用现有 Invocation/查询/等待服务；Web 在应用详情增加接入配置与诊断。协议适配不复制工作流执行逻辑，也不赋予网页生成 Agent 业务 MCP 能力。

功能测试编号见 [验收矩阵](05-e2e-acceptance.md) 的 E9-M01–M06 与 E9-X01–X04。主交付任务为 P9-05，不能用 Echo Server 的 SDK 示例代替正式应用与真实客户端验收。

## 实现细化（2026-11-01）

MCP 访问后缀在本部署全局归属唯一应用，使未登录的 OAuth 资源发现能够返回唯一应用的 Scope；同应用的多条保留发布可共享后缀。业务工具输入包含 `publicationRevision`，由发现结果给出展示版本；未删除的旧修订仍可新提交，同一 requestId 的原调用仍按原绑定重放。三个辅助工具不受页面发布影响。删除后缀的最后一条发布会移除该地址，既有任务仍可通过该应用其他可用入口或正式任务 API 按归属访问。

MCP 修订不包含需要跨域复制的 HTML，沿用 Publisher Admission Outbox，在 Runtime 同一事务核对已发布 Bundle、完整输入输出契约与预期序号。Head 仅分配单调发布序号，访问路由按后缀与未删除发布解析；路由表唯一占用全局后缀，允许同应用多条发布共享。仍保留的发布持有 Bundle 引用，删除仅释放该引用。Hydra 固定官方 OSS v26.2.0 镜像及摘要，独立 MySQL 与 `agentx-oauth` Secret；公共 OAuth 路由由现有 Runtime TLS 入口固定代理，Admin 仅由 Control/Runtime 的网络策略访问。个人客户端预登记并绑定具体发布的资源地址，采用应用 Scope、精确入口 Audience、PKCE、显式同意、opaque Token 与逐请求 introspection；更改后缀不影响旧客户端，连接新后缀需为其登记客户端，不开放动态匿名客户端登记。

## 9. 补充输入与错误响应的协议约定

发布修订冻结 `waitInputSchema`：由该业务版本全部等待输入的 responseSchema 合并生成，只有一个类型时直接使用；多个类型使用 JSON Schema `anyOf`。没有等待节点时为不可满足的 Schema，未声明类型的等待仍接受原始 JSON。`submit_task_input.content` 合并该应用已发布 MCP 与网页版本的真实等待契约，去重后提供具体字段和类型；当全部分支可确定类型时补充等价的显式 `type`，帮助模型正确处理联合类型。旧版本契约仍可用于原任务，不扩大到任意猜测的类型。客户端必须读取指定待办的 `pendingInputs[].responseSchema`；服务端始终按原任务当前 waitId 的精确 Schema 校验。对象、数组直接发送 JSON 值，不转成 JSON 字符串。

业务工具成功时返回符合 TaskView 的 structuredContent。校验失败、越权、修订冲突等操作错误采用标准 MCP `isError` 与文本内容，保留错误码和字段错误，不把错误对象放进成功结果的 structuredContent，以免客户端输出校验遮盖真实原因。
